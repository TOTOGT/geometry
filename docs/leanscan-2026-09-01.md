## Finding 1 — the 2026-08-30 audit log reported nothing about mathematics

`~/Desktop/leanaudit-2026-08-30.log` ends `0 ok, 252 failed`. **None of the 252 is a
compile result.** Every one is the same three lines:

```
tools/leancheck.sh: line 32: cd: 3M: No such file or directory
  FAIL     1s  <file>.lean  (1 errors)
          no such file or directory (error code: 4294967294)
```

`leancheck.sh` did `cd "$PROJ"` at line 25 and then resolved each argument at line 32
with `f=$(cd "$(dirname "$f")" && pwd)/...`. After that first `cd`, a relative
argument resolved against `~/Desktop/geometry` instead of the caller's directory, so
`3M/Conformal.lean` was looked up as `~/Desktop/geometry/3M/Conformal.lean`. The word
"error" inside the failure message then made `grep -c 'error'` report "1 errors", and
the summary counted every miss as a failure. A path bug wearing the costume of a
mathematical one.

Repaired 2026-09-01:

- arguments resolve to absolute paths **before** `cd "$PROJ"`
- unresolvable paths count as `skipped`, print separately, and can never again appear
  in the failed column
- `rc != 0` with no error output now prints `toolchain did not run — rc=N`, because
  that means lake never started, not that the file is broken
- pre-repair copy at `docs/ml-evidence/leancheck.sh.bak-before-2026-09-01-pathfix`

Verified on the exact failing case (a relative argument from `~/Desktop`): resolution
now reaches the compile step, and two bad paths report as `2 skipped`, not `2 failed`.
The compile leg was not exercised in that check — `lake` lives in `~/.elan`, outside
the folders the session could reach.

`~/Desktop/leanaudit-2026-09-01.log` exists and is **0 bytes**, with no `lake`, `lean`
or `leancheck` process running. Nothing has run today.

## Finding 3 — a macOS checkout cannot see the whole corpus

Discovered 2026-09-01 while cloning `sluing/neuro`. Git reported colliding paths:

```
'DiscreteDM3.lean'  'discreteDm3.lean'  'discretedm3.lean'
'lean/AXLE_V8.1.lean'  'lean/AXLE_v8.1.lean'
'book3/chW-wigner.html'  'book3/chw-wigner.html'
```

These are distinct tracked files whose names differ only in case. APFS is
case-insensitive by default, so **only one of each group is ever in the working tree on
the Mac**, and git then reports the survivor as "modified" because its content does not
match the index entry for the name it landed under. Committing that apparent
modification overwrites one tracked file with another's content.

They are not cosmetic duplicates. Checked on a case-sensitive filesystem:

| group | bytes | decls | `sorry` | verdict |
|---|---:|---:|---:|---|
| `DiscreteDM3.lean` | 2,732 | 4 | 0 | **different file** |
| `discreteDm3.lean` = `discretedm3.lean` | 6,511 | 4 | 1 | **different file** |
| `lean/AXLE_V8.1.lean` | 4,280 | — | — | header comment only |
| `lean/AXLE_v8.1.lean` | 4,362 | — | — | adds a scoping sentence |
| `book3/chW-wigner.html` = `book3/chw-wigner.html` | 30,122 | — | — | byte-identical |

The `DiscreteDM3` pair is the one that matters: same four declarations, one carries a
`sorry` and one does not. Which name is canonical decides a corpus `sorry` count, and a
blind commit on macOS decides it by accident.

**Consequence for every count in this document.** The census above was run on a
case-sensitive filesystem and therefore counted files a Mac checkout cannot hold. Any
Lean count previously run on the Mac was, for the same reason, short by the hidden
siblings. Neither number was wrong about the repository; they were measuring different
things, and nothing said so. A corpus count should state the filesystem it was taken on.

**Not repaired here.** Renaming or deleting a tracked file in `sluing/neuro` is the
author's call, and the `DiscreteDM3` pair needs a decision about which is canonical
before either is touched.

## Run

```bash
cd ~/Desktop
bash geometry/tools/leancheck.sh --audit \
  geometry/NbonacciLadder.lean \
  geometry/SpiralReturnObstruction.lean \
  geometry/TripleAlphaDm3.lean \
  GTCT/NonCommutativity_v4.lean \
  2>&1 | tee ~/Desktop/leanaudit-$(date +%F).log

tail -3 ~/Desktop/leanaudit-$(date +%F).log
grep -c '^  OK\|^  FAIL' ~/Desktop/leanaudit-$(date +%F).log
```

The gate is the `audit:` line, not the OK. A file can compile, contain no `sorry`, and
still be worthless; `--audit` is what prints how many declarations trust `sorryAx` or
`native_decide`. A `skipped` count above zero means paths, not mathematics.
