Unit 1 · Introduction to Software Engineering Concepts

Software engineering applies engineering discipline to building and maintaining software that is correct, affordable and changeable. The lifecycle runs through requirements, design, implementation, testing, deployment and maintenance, and maintenance usually costs more than first construction. Process models differ in how they order these: waterfall (sequential, good when requirements are stable), incremental and spiral (risk-driven), and agile (short iterations with feedback). Requirements are functional (what the system does) or non-functional (performance, security, usability).

Self-check Give one project type that suits waterfall and one that suits agile, and the property of each that decides it.

Unit 2 · Software Design and Architecture

Design manages complexity through modularity: high cohesion inside modules and low coupling between them. The SOLID principles guide object-oriented design, and design patterns (factory, observer, strategy and others) name recurring solutions. Architecture is the top-level structure: layered, client-server, microservices, event-driven or pipe-and-filter. Each choice trades qualities: microservices scale teams and deployments independently but add network failures and operational cost. UML diagrams (class, sequence, component) communicate designs.

Record the reason for a design decision when you make it. Later maintainers need the why, not only the what.

Self-check A monolith has become slow to change. Name two reasons to split it into services and two costs of doing so.

Unit 3 · Emerging Industry Trends in Software Engineering

The course names AI and machine learning, DevOps, cloud technologies and cybersecurity. DevOps joins development and operations through automation: continuous integration builds and tests every change, continuous delivery keeps software releasable, and infrastructure is described as code. Cloud services offer infrastructure, platform and software as services, with elastic scaling and pay-per-use. AI tools assist coding and testing but their output still needs review, and ML components add data and model versioning. Security shifts left, into design and the pipeline.

Self-check Describe what a CI pipeline should do on every commit and what failure should stop.

Unit 4 · Advanced Problem-Solving in Software Engineering

Problem solving follows a loop: understand and reproduce, decompose, hypothesize, test, and verify. Testing levels are unit, integration, system and acceptance; techniques include equivalence partitioning and boundary-value analysis. White-box coverage is judged on the control-flow graph, where cyclomatic complexity V = E - N + 2P gives the number of independent paths and a lower bound on test cases for full branch coverage.

Worked example computed. A routine has a while loop containing an if-else. Its control-flow graph has nodes 1-8 and edges 1→2, 2→3, 2→7, 3→4, 3→5, 4→6, 5→6, 6→2, 7→8: that is E = 9, N = 8, P = 1, so V = 9 - 8 + 2 = 3. The two decisions (the loop test and the if) give 2 + 1 = 3, matching. Three independent paths need at least three tests.

Debugging works best by bisecting: shrink the failing input or the changed code until the cause is isolated, and write a regression test before fixing.

Self-check For a function with one if inside another if, count decisions and give V; then list a test input idea for each independent path.

Unit 5 · Role-Specific Skills in Software Engineering

The course surveys roles: software architect (structure and quality attributes), QA engineer (test strategy and automation), full-stack developer (front end, back end and data), and security engineer (threat modelling and secure practice). Common skills are version control, code review, reading unfamiliar code, writing clear documentation and estimating honestly. Estimation models give ranges, not promises. computed The basic COCOMO organic-mode model estimates effort as 2.4 × (KLOC)1.05 person-months; for a 10 KLOC project that is 26.9 person-months, and schedule 2.5 × effort0.38 is about 8.7 months. Treat that as a rough sanity check, since it was fitted on old projects and depends on inputs you can only guess.

Self-check Which role would own each of: a threat model, a flaky-test report, an API contract? State why.

Unit 6 · Team Collaboration and Agile Practices

Agile values working software, collaboration and responding to change. Scrum organizes work in fixed sprints with roles (product owner, scrum master, team), events (planning, daily scrum, review, retrospective) and artifacts (product backlog, sprint backlog, increment). Kanban visualizes flow and limits work in progress. Practices include user stories with acceptance criteria, pair programming, code review, trunk-based development and refactoring. Healthy teams keep a shared definition of done and handle conflict about technical choices with evidence.

Self-check Write one user story with two acceptance criteria for a password-reset feature.

Unit 7 · Real-World Applications and Problem Solving

Real projects are messy: unclear requirements, legacy code, and deadlines. Useful habits are to write the smallest slice that delivers value, to measure before optimizing, to keep a risk list, and to automate repeated checks. Technical debt, shortcuts that speed now and cost later, should be tracked and paid down deliberately. Post-incident reviews should be blameless and end in specific changes. Project-based learning in this unit means choosing a realistic scenario, scoping it, designing, building a thin version and reflecting on what the evidence showed.

Self-check Pick a small real problem near you and list its smallest valuable slice, one risk and one measurement.

Unit 8 · Evaluating the Business Impact of Software Solutions

Software is judged by outcomes: revenue, cost, risk and user value. Frame decisions with costs and benefits over time, for example net present value, return on investment and payback period, and include maintenance, support and opportunity cost. Metrics should connect to goals: deployment frequency and lead time for delivery speed, change-failure rate and recovery time for stability, and adoption and retention for value. Beware vanity metrics. Ethics and compliance, such as privacy and accessibility, are business risks as well as moral ones.

Self-check A feature costs 40,000 to build and returns 15,000 a year. Compute simple payback and say what that number leaves out.
