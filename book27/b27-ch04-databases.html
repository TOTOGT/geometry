Unit 1 · Database Systems Fundamentals

Before databases, applications kept their own files. That file-processing approach duplicates data (redundancy), lets copies disagree (inconsistency), ties programs to file formats, and makes concurrent access and security hard. A database management system (DBMS) centralizes data and provides a data model, a query language, integrity rules, concurrency control, recovery, and access control. This is the first learning outcome of the course: compare an RDBMS with file processing and explain why the RDBMS is needed.

The three-schema architecture separates the external views users see, the conceptual schema for the whole database, and the internal storage schema. It gives data independence: you can change storage without rewriting programs (physical independence) and change the conceptual schema without breaking every view (logical independence). Typical actors are database designers, application developers, end users and the database administrator (DBA).

Self-check Name three problems a spreadsheet-per-department approach causes that a shared DBMS solves, and say which of the three schema levels each fix lives at.

Unit 2 · Entity-Relationship Modelling

The ER model describes a domain before choosing tables. An entity is a thing with an identity (Student, Course), an attribute is a property (name; a key attribute identifies the entity), and a relationship links entities (Student enrols in Course). Relationships carry cardinality (one-to-one, one-to-many, many-to-many) and participation (total or partial). A weak entity has no key of its own and depends on an owner entity (a Dependent identified by its Employee plus a name).

Mapping ER to relations follows rules: an entity becomes a table with its key; a one-to-many relationship puts the key of the “one” side into the “many” side as a foreign key; a many-to-many relationship becomes its own table whose key combines both keys; multivalued attributes get their own table. Justify each modelling choice by the requirement it serves, because the course asks for justifications based on database principles.

Self-check A hospital stores doctors, patients and appointments. Sketch the entities and cardinalities, and say which relationship becomes its own table and why.

Unit 3 · Relational Data Modelling

A relation is a set of tuples over named attributes. A superkey identifies a tuple; a candidate key is a minimal superkey; the primary key is the chosen one. Two integrity rules matter: entity integrity (a primary key is never null) and referential integrity (a foreign key is null or matches an existing key). Relational algebra gives the query core: select σ (rows), project π (columns), join ⋈, union, difference, and rename.

Normalization removes redundancy using functional dependencies (FDs). X → Y means any two tuples that agree on X agree on Y. The closure X+ is every attribute determined by X. First normal form requires atomic values; 2NF removes partial dependencies on part of a key; 3NF removes transitive dependencies; BCNF requires every determinant to be a superkey.

Worked example computed. Relation R(A, B, C, D, E) with FDs A → B, B → C, CD → E. Then A+ = ABC and (AD)+ = ABCDE. A and D never appear on a right-hand side, so every key must contain both, and AD already determines everything, so the only candidate key is AD. The FD A → B has a left side that is part of the key and a non-key right side, a partial dependency, so R is not in 2NF. Fixing it means splitting the relation so each non-key attribute depends on the whole key of its table.

Self-check Find the candidate keys of S(P, Q, R, T) with FDs P → Q and QR → T, then state the highest normal form S satisfies and why.

Unit 4 · Structured Query Language

SQL has a data definition part (CREATE TABLE, constraints, ALTER), a data manipulation part (SELECT, INSERT, UPDATE, DELETE), and control statements for transactions and permissions. A query reads in this logical order: FROM (with joins), WHERE, GROUP BY, HAVING, SELECT, ORDER BY. Aggregates (COUNT, AVG, SUM) collapse groups; WHERE filters rows before grouping and HAVING filters groups after. Beware NULL: it is not equal to anything, comparisons with it are unknown, and COUNT(col) skips it.

Worked example computed. Tables dept(1 Sales, 2 Engineering, 3 Legal) and emp(Ana, Sales, 50000; Bo, Eng, 80000; Cy, Eng, 90000; Di, Sales, 60000; Ed, no department, 40000). Run in SQLite:

SELECT d.name, COUNT(e.id), AVG(e.salary)
FROM dept d LEFT JOIN emp e ON e.dept_id = d.id GROUP BY d.id;

returns Sales, 2, 55000; Engineering, 2, 85000; Legal, 0, NULL. The left join keeps Legal even with no employees, so its count is 0 and its average is NULL. An inner join emp JOIN dept returns 4 rows, dropping Ed because his department is NULL. HAVING AVG(e.salary) > 70000 returns only Engineering.

Self-check Rewrite the query so Legal is dropped, then explain in one sentence why replacing HAVING with WHERE would be an error.

Unit 5 · Database Administration

The DBA installs and configures the system, creates schemas and users, monitors performance, plans capacity, and keeps the database available. A central tool is the index, usually a B-tree, which trades extra storage and slower writes for faster lookups on the indexed columns. A query that filters or joins on an unindexed column forces a full scan; the query plan shows which choice the optimizer made. The system catalog stores metadata about tables, columns, indexes and users.

The course ties administration to ethics: DBAs see sensitive data, so access should follow least privilege, changes should be logged, and personal data should be handled under the rules that apply to it. Good habits are documented schemas, tested changes in a staging environment, and routine monitoring rather than firefighting.

Self-check A report query slows down as a table grows from thousands to millions of rows. Name two checks you would make before adding an index, and one cost of adding it.

Unit 6 · Transaction Management

A transaction is a unit of work that must satisfy ACID: atomicity (all or nothing), consistency (constraints hold before and after), isolation (concurrent transactions do not see each other's partial work) and durability (committed work survives failures). Without isolation come the classic anomalies: lost update, dirty read, non-repeatable read and phantom read. SQL's isolation levels (read uncommitted, read committed, repeatable read, serializable) trade protection against performance.

A schedule is conflict serializable if it is equivalent to some serial order. Build a precedence graph: draw an edge Ti → Tj when an operation of Ti precedes a conflicting operation of Tj (same item, different transactions, at least one write). The schedule is serializable exactly when the graph has no cycle. computed For S1 = r1(X) w1(X) r2(X) w2(X) r1(Y) w1(Y) r2(Y) w2(Y), the edges are T1→T2, no cycle, so S1 is equivalent to T1 then T2. For S2 = r1(X) r2(X) w1(X) w2(X), the edges are T1→T2, T2→T1, a cycle, so S2 is not serializable. Two-phase locking (acquire locks, then only release) guarantees serializability but can deadlock, which the system detects or prevents.

Atomicity demo computed. A table with 5 rows had one row inserted inside a transaction (6 rows visible inside); after ROLLBACK it had 5 rows again.

Self-check Two transactions both read a balance of 100 and each subtracts 30, writing 70. Name the anomaly, and name one isolation mechanism that prevents it.

Unit 7 · Database Security, Backup and Recovery

Security covers authentication (who are you), authorization (what may you do), and auditing. SQL uses GRANT and REVOKE on tables, columns and views; views can hide columns or rows. Common threats are weak credentials, over-privileged accounts, unencrypted data and SQL injection, where input text changes the meaning of a query. Defenses are parameterized queries, least privilege, input validation, encryption at rest and in transit, and patching.

Recovery rests on the log. With write-ahead logging, changes are recorded in the log before data pages are written, so after a crash the system redoes committed work and undoes uncommitted work; checkpoints limit how far back it must look. Backups are full, incremental or differential, taken on a schedule and, importantly, restore-tested. Two numbers drive the plan: how much data loss is tolerable (recovery point objective) and how long recovery may take (recovery time objective).

Self-check A nightly full backup plus an hourly log backup is in place. What is the worst-case data loss, and what must be true for a point-in-time restore to work?

Unit 8 · Emerging Database Technologies

Relational systems are not the only model. NoSQL families include key-value stores, document stores, wide-column stores and graph databases, each suited to a different access pattern. They often relax strict consistency to scale across machines. The CAP theorem says a distributed store facing a network partition must choose between consistency and availability, and many systems use eventual consistency. NewSQL tries to keep SQL and ACID at scale. Data warehouses and column stores serve analytics, and big-data platforms process data too large for one machine.

The course asks you to compare models by design, implementation and query language. A useful comparison table has columns for data model, query style, consistency choice, typical workload and main risk, and one row for each of the relational, document, key-value and graph models.

Self-check Pick a social-network feature such as “friends of friends”. Which database model fits it best and which fits worst, and what query would each need?
