Unit 1 · The Role of Algorithms in Computing

An algorithm is a finite, precise procedure that maps inputs to outputs. Two questions govern it: is it correct, and how expensive? Correctness is shown by proof. A loop invariant is a statement true before the loop, kept true by each iteration, and which gives the result when the loop ends; you prove initialization, maintenance and termination. Induction proves recursive algorithms the same way: base case, then assume the claim for smaller inputs.

Algorithms matter because hardware speedups do not rescue a poor growth rate; a better algorithm beats a faster machine as input grows.

Self-check State a loop invariant for finding the maximum of an array and prove its three parts in two sentences each.

Unit 2 · Growth of Functions and Asymptotic Analysis of Algorithms

Running time is counted as a function of input size n and compared by growth. Big-O gives an upper bound (f = O(g) if f ≤ c·g for large n), Omega a lower bound and Theta a tight bound. The usual ladder, slow to fast growing, is 1, log n, n, n log n, n², n³, 2n, n!. Constants and lower-order terms drop out: 3n² + 10n + 7 = Θ(n²).

Recurrences describe recursive costs. The master theorem solves T(n) = aT(n/b) + f(n): compare f(n) with nlogb a. If f is polynomially smaller, T = Θ(nlogb a); if equal, Θ(nlogb a log n); if larger (with a regularity condition), Θ(f). Merge sort has T(n) = 2T(n/2) + n, so Θ(n log n).

Self-check Solve T(n) = 4T(n/2) + n and T(n) = 2T(n/2) + n² with the master theorem, and say which case each is.

Unit 3 · Divide and Conquer

Divide and conquer splits a problem into smaller instances of itself, solves them recursively and combines the answers. Merge sort, quicksort, binary search and Strassen's matrix multiplication are examples. The cost is the recurrence from Unit 2: work to divide and combine plus the cost of the subproblems.

Worked example computed. Merge sort on [38, 27, 43, 3, 9, 82, 10, 5] makes 17 comparisons while merging and returns [3, 5, 9, 10, 27, 38, 43, 82]. For n = 8 the worst case is n log₂ n - n + 1 = 17 comparisons, so this input hits the worst case. Binary search halves the range each step: searching the sorted array for 43 takes 3 probes and finds it at index 6; the worst case is floor(log₂ n) + 1 = 4 probes for n = 8.

Self-check Why does merge sort need extra memory but binary search does not? State the space cost of each.

Unit 4 · Analysis of Sorting Algorithms

Insertion, selection and bubble sort are Θ(n²) in the worst case; insertion sort is Θ(n) on nearly sorted data. Merge sort and heapsort are Θ(n log n) in the worst case; quicksort is Θ(n log n) on average and Θ(n²) in the worst case, which a good pivot rule makes rare. Merge sort is stable (equal keys keep their order); quicksort and heapsort are not by default.

Any sort that works only by comparing elements needs Ω(n log n) comparisons in the worst case: the decision tree has n! leaves and height at least log₂(n!) = Θ(n log n). Counting sort and radix sort beat this by not comparing, at the price of assumptions about the keys.

Self-check You must sort a million records by date and then stably by customer. Which algorithm properties do you need, and in which order do you sort?

Unit 5 · Data Structures and Algorithms

Choose a structure by the operations you need. Arrays give O(1) indexing but costly insertion in the middle; linked lists give O(1) insertion at a known node but O(n) search; stacks and queues restrict access to one end or two; heaps give O(log n) insert and extract-min and back priority queues; balanced binary search trees (AVL, red-black) give O(log n) search, insert and delete in sorted order. The Java textbooks the course uses implement these; the ideas are language-independent.

Trees add traversals: in-order on a binary search tree visits keys in sorted order, and a tree of height h costs O(h), which is O(log n) only if the tree stays balanced. An unbalanced insert sequence can degrade a plain BST to a list.

Self-check Insert 10, 20, 30, 40, 50 in order into an empty plain BST and state the height; then say what a balanced tree would do differently.

Unit 6 · Hash Tables and their Applications

A hash table maps keys to array slots with a hash function, giving O(1) expected lookup when the load factor stays bounded. Two keys landing in one slot is a collision, resolved by chaining (each slot holds a list) or open addressing (probe for another slot). A good function spreads keys evenly; with n keys and m slots the expected chain length is the load factor n/m.

Worked example computed. Insert keys 50, 700, 76, 85, 92, 73, 101 into 7 slots using h(k) = k mod 7 with chaining. The slots hold: slot 0: [700]; slot 1: [50, 85, 92]; slot 2: empty; slot 3: [73, 101]; slot 4: empty; slot 5: empty; slot 6: [76]. The load factor is 7/7 = 1, and the longest chain has 3 keys. Hash tables give no sorted order and have O(n) worst case if everything collides.

Self-check Rehash the same keys into 11 slots with k mod 11 and report the longest chain.

Unit 7 · Graphs and Algorithms

A graph is vertices and edges, stored as an adjacency list (space O(V+E), good for sparse graphs) or a matrix (O(V²), O(1) edge test). Breadth-first search explores by distance in edges and finds shortest paths in unweighted graphs; depth-first search underlies topological sort, cycle detection and strongly connected components. With non-negative weights, Dijkstra's algorithm repeatedly settles the nearest unsettled vertex; with a binary heap it runs in O((V+E) log V). Bellman-Ford handles negative edges. Minimum spanning trees come from Kruskal or Prim.

Worked example computed. Edges S-A 7, S-B 2, B-A 3, B-C 8, B-D 5, A-C 1, D-C 2, C-T 4, D-T 9 (directed as written). Dijkstra from S gives distances S = 0, A = 5, B = 2, C = 6, D = 7, T = 10, and the shortest path to T is S → B → A → C → T with length 10. Note the direct edge S-A costs 7 but the route through B costs 5.

Self-check Why does Dijkstra fail when an edge has negative weight? Give a three-vertex counterexample.

Unit 8 · String Matching Algorithms

The naive search tries every alignment, O(nm) for text length n and pattern length m. Knuth-Morris-Pratt precomputes a failure table: for each prefix of the pattern, the length of the longest proper prefix that is also a suffix. On a mismatch the pattern shifts using the table and the text pointer never moves back, giving O(n + m). Rabin-Karp compares rolling hashes, and Boyer-Moore skips ahead using the pattern's last characters.

Worked example computed. For the pattern ABABC the failure table is [0, 0, 1, 2, 0]. Searching the text ABABABCABABC, the pattern occurs at positions 2 and 7 (counting from 0).

Self-check Build the failure table for AABAAB by hand and explain what the last entry means.
