Unit 1 · Introduction to Operating Systems

An operating system (OS) is the software layer between applications and hardware. It does four jobs: it abstracts hardware (files instead of disk blocks), multiplexes scarce resources among programs, protects programs from each other, and provides services through system calls. Hardware support makes this possible: a timer interrupt lets the OS regain the CPU, and dual-mode operation (user mode and kernel mode) stops ordinary programs from executing privileged instructions.

The classic evolution runs from batch systems to multiprogramming and time-sharing to today's multicore, mobile and cloud systems. Keep the distinction between mechanism (how something is done, such as a context switch) and policy (what should be done, such as which process runs next).

Self-check Why must the instruction that disables interrupts be privileged? Describe what an ordinary program could do if it were not.

Unit 2 · Understanding System Structures

System calls are the OS's public interface; they fall into process control, file management, device management, information maintenance and communication. A call traps into the kernel, which checks arguments, does the work and returns. Structures differ in where the code lives: a monolithic kernel runs most services in kernel mode (fast, large trusted base), a microkernel keeps only the essentials in the kernel and runs the rest as user-level servers (smaller trusted base, more message passing), and layered and modular designs sit between. Virtual machines apply the same idea one level down by presenting each guest a virtual copy of the hardware.

Self-check Name one advantage and one cost of a microkernel compared with a monolithic kernel, and say what in the design causes each.

Unit 3 · Fundamental Principles of Operating Systems

A process is a program in execution: code, data, stack, heap and a record of its state in the process control block. States are new, ready, running, waiting and terminated. A thread is a unit of execution inside a process; threads share the address space but have their own stack and registers. A context switch saves one process's state and loads another's; it is pure overhead.

CPU scheduling decides which ready process runs. Common metrics are waiting time (time spent ready), turnaround time (finish minus arrival) and response time. Worked example computed. Processes (arrival, burst): P1 (0, 5), P2 (1, 3), P3 (2, 8), P4 (3, 6). Non-preemptive first-come-first-served gives average waiting time 5.75 and average turnaround 11.25. Shortest-job-first (non-preemptive) gives 5.25 and 10.75. Round robin with quantum 4 gives 9.25 and 14.75. Shortest-job-first minimizes average waiting among non-preemptive orders but can starve long jobs and needs burst estimates; round robin is fairer for response time and pays more in context switches.

Self-check Rework the example by hand for first-come-first-served and confirm the two averages. Then say which process waits longest under SJF and why.

Unit 4 · Device Interaction and Management

Devices connect through controllers and are driven by device drivers. The CPU can poll a device, take an interrupt, or hand bulk transfers to a DMA controller that moves data to memory without per-byte CPU work. The kernel's I/O subsystem adds buffering, caching, spooling and error handling, and presents uniform interfaces to block and character devices.

For disks, seek time dominates, so scheduling orders requests to cut head movement: first-come-first-served, shortest-seek-time-first, SCAN (elevator) and its variants. Solid-state drives have no head, so those policies matter less, but wear and write amplification matter instead.

Self-check A disk head is at cylinder 53 with requests at 98, 183, 37, 122, 14, 124, 65, 67. Without computing everything, say why SSTF might starve some request.

Unit 5 · Resource Allocation Strategies

When concurrent processes share data, a race condition makes the result depend on timing. A critical section needs mutual exclusion, progress and bounded waiting. Tools are locks, semaphores and monitors; the classics are producer-consumer, readers-writers and dining philosophers.

Deadlock needs four conditions at once: mutual exclusion, hold-and-wait, no preemption and circular wait. Remove any one to prevent it. The banker's algorithm avoids deadlock by granting a request only if the system stays in a safe state, meaning some order exists in which every process can finish. Worked example computed. Three resource types, available (3, 3, 2), five processes P0-P4 with the allocation and maximum matrices of the standard textbook example (allocations P0 (0,1,0), P1 (2,0,0), P2 (3,0,2), P3 (2,1,1), P4 (0,0,2); maxima P0 (7,5,3), P1 (3,2,2), P2 (9,0,2), P3 (2,2,2), P4 (4,3,3)). Need = max minus allocation gives P0 (7,4,3), P1 (1,2,2), P2 (6,0,0), P3 (0,1,1), P4 (4,3,1). A safe sequence found by the scan is P1, P3, P4, P0, P2, so the state is safe. Safe is a promise that a way out exists, not that the system is idle; unsafe does not mean deadlocked, only that deadlock is possible.

Self-check Explain why the circular-wait condition is the one most often broken in practice, for example by ordering locks.

Unit 6 · Operating System Services

The file system gives names and structure to persistent data: files, directories, metadata and access control. Allocation can be contiguous, linked or indexed (the Unix inode is an indexed scheme with direct and indirect pointers). Free space is tracked by bitmaps or lists. Journaling file systems write intent to a log first so a crash leaves the structure consistent, the same idea as write-ahead logging in databases.

Protection and security answer different questions: protection controls which processes may access which resources (access-control lists, capabilities), security defends against threats from outside that model. Authentication, least privilege and auditing are the working habits. Networking services, naming and time are also OS services in distributed settings.

Self-check A file has permissions rw-r----- owned by user alice, group staff. State exactly who can read it and who can write it.

Unit 7 · Enhancing System Efficiency

Memory management turns the programmer's contiguous addresses into scattered physical memory. With paging, a virtual address splits into a page number and an offset; the page table maps pages to frames; a TLB caches recent translations. Worked example computed. With 4096-byte pages, virtual address 20000 is page 4, offset 3616 (20000 = 4 x 4096 + 3616). If page 4 sits in frame 9, the physical address is 9 x 4096 + 3616 = 40480.

Virtual memory lets a process use more memory than is resident by faulting pages in on demand. When memory is full, a replacement policy picks a victim. computed For the reference string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1 with 3 frames, FIFO gives 15 faults, LRU 12 and the optimal policy 9; with 4 frames they give 10, 8 and 8. Optimal needs the future and so is a yardstick, not an algorithm you can run. Belady's anomaly computed: FIFO can fault more with more frames; on 1,2,3,4,1,2,5,1,2,3,4,5 it takes 9 faults with 3 frames and 10 with 4. LRU does not have this anomaly. Too little memory causes thrashing, where the system spends its time paging; the working-set idea limits it.

Self-check For the Belady string, list the frame contents after each reference for FIFO with 3 frames and check the fault count.

Unit 8 · Modern Computing Environments

Today's systems are multicore, virtualized and distributed. Hypervisors share hardware among guest operating systems; containers share one kernel and isolate processes with namespaces and resource limits, which is lighter but a weaker boundary. Cloud platforms schedule thousands of such units. Mobile and embedded systems add energy limits and real-time deadlines, where a real-time OS guarantees bounded response rather than best average speed.

Performance, inter-process communication (pipes, shared memory, message passing, sockets) and security remain the three levers the course's fourth outcome names. When comparing environments, state the workload, the isolation you need, and what you give up for it.

Self-check Pick a hospital monitoring device and a web server farm. Which needs a real-time OS, which needs containers, and why?
