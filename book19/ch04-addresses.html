Claima count and a proposed rule
Before asking whether a proof is right, a reader can ask something cheaper: does the file the page names exist? Across this corpus, 98 file names do not resolve anywhere in the repository. This chapter was planned around a count of 110. That number turned out to be the count of files that do exist.

2 · The artefact

A tool read another tool

The first run today reported 99 names and 385 citations. The top entry was FILE.lean, on 96 pages. No page claims that file. The phrase comes from the one-click download box that tools/run_yourself.py (R26) writes: "then lake env lean FILE.lean". The address checker read the box as prose. COMPUTED

The fix is one line. lean_addresses.py now strips the generated blocks (po-run, po-gss, po-related, po-subject) before it scans, the same rule run_yourself.py already follows. This is the second time in a week that a generator's output leaked into another checker's input.

The planned 110 The index said "110 .lean names cited across the corpus resolve nowhere". No run of that figure was recorded. The repository has exactly 110 tracked .lean files, and the tool's header line prints "110 corpus .lean files". The plan most likely took the wrong line. It is corrected here. COMPUTED
3 · The smallest rule

Name only what resolves

The books written this session (XI, XII, XVIII, XX, XXI) cite no name that resolves nowhere. They were written after R26, whose download box links only to files that exist. If a page offers a download link, the address has to be real. COMPUTED

Proposed rule (R27) A new or edited page may name X.lean only if lean_addresses.py resolves it. The 98 existing names are frozen as a baseline, which may shrink but never grow. PROPOSAL
